[[domain|catalog]] owns the product information that customers browse and buy. It is split into two systems with different consistency needs.

## System context map

<Map />

## Product Catalog System

[[system|product-catalog-system]] is the source of truth. [[service|Product API]] handles product commands and reads from **Product Database**. Product changes are captured through an outbox and published by [[service|Product Search Publisher]].

Key contracts:

- [[event|catalog/create-product]]
- [[event|catalog/update-product]]
- [[event|catalog/delete-product]]
- [[event|catalog/get-product]]
- [[event|product-platform/catalog/product-created]]
- [[event|product-platform/catalog/product-updated]]
- [[event|product-platform/catalog/product-deleted]]

## Search System

[[system|search-system]] serves product discovery through [[service|Search API]] and [[event|catalog/search-products]]. It maintains **Search Index** from product events.

The Search System should be treated as eventually consistent with the Product Catalog System. If a merchandiser updates a product, the product database is immediately authoritative; search visibility follows after indexing.

## Decision context

The product catalog has several architecture decisions documented directly on the system:

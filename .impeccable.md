## Design Context

### Users

Platform and backend engineers, tech leads and architects at companies with
many repositories and many teams. They arrive from a README, a pull request
check that failed, or a colleague's link. They want to know, fast: what does
this read from my code, what does the site look like, and will the PR gate
name the team I am about to break. Coding agents read the same pages through
`llms.txt` and Markdown twins.

### Brand Personality

Exact, annotated, unhurried. The catalog is compiled from code and every fact
says where it came from. Confident without shouting: it shows its sources
instead of making claims. Emotional goal: trust ("I can see how sure it is")
and relief ("nobody has to keep this up to date").

### Aesthetic Direction

- Chosen direction: "Living map". The hero is an interactive map of the
  company's repositories, with their docs, events and services on it. Crisp
  blueprint grid in light mode, near-black greys in dark.
- Type: Inter for the interface and prose; JetBrains Mono for code, keys and
  paths. Weight and size do the hierarchy.
- Message order: first, every team's docs, events and services in one place;
  contracts and the pull request check are the spine, second.
- References: the autotel docs (https://jagreehal.github.io/autotel/) for
  family resemblance and a hero built around a real product artifact;
  eventcatalog.dev for polish and its calm rail-and-sidebar navigation. Learn from both, copy
  neither (no green brand accent, no kind-coloured chrome).
- Product chrome: a section rail beside the sidebar, and a header led by
  search. The marketing home stays full-bleed; catalog pages use the rail.
- Anti-references: generic Starlight defaults, identical icon-card grids,
  vanity stat tiles, purple gradients, glowing dark mode, EventCatalog clones.
- Signature: provenance. Extracted (teal), declared (blue), inferred (amber,
  dashed). Colour is spent on provenance and almost nothing else.
- Both light and dark themes, each designed, neither an afterthought.

### Design Principles

1. Show the artifact, not a description of it: real code, real catalog
   output, a real failing PR check.
2. Every claim sits beside its source, the way the product does it.
3. Colour means provenance. Kinds and sections are told apart by type,
   space and structure, not colour.
4. Rhythm over repetition: varied section structures, no card grids of
   equal tiles.
5. Plain, specific words. Sentence case. No eyebrow labels for decoration.
